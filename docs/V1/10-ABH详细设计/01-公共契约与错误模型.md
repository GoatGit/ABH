> 本文定义字段与语义；机器 Schema 的生成和放行见 [Contract Package](05-Contract-Package与一致性检查.md)。

## 1. 基础类型

| 类型 | 字段与约束 |
|---|---|
| EntityRef | `{ type, id, version }`；type 为已注册命名空间类型，id 为服务端 UUID，version 为正整数；无版本读取使用独立 Selector，不能伪造 version=0 |
| CapabilityRef | `{ kind, id, version, digest }`；id 为 Pack 注册的命名空间名称、version 为精确 SemVer；与数据库 EntityRef 分开，不把版本范围作为固定运行引用 |
| AuthorityRef | EntityRef 的闭合联合，type 仅为 `abh.mission-authority` 或 `abh.execution-authority`；持久权限依据，不能代替当前授权 Snapshot |
| Target | `{ objectRef, action, scopeRefs }`；action 是已注册业务动作；scopeRefs 从服务端对象关系解析后核对 |
| Money | `{ amount, currency }`；amount 为主货币单位十进制字符串；currency 为 ISO 4217；规范形式无指数、无前导 +、无负零 |
| Decimal | 整数部分最多 26 位、小数部分最多 12 位；数据库 numeric(38,12)；超范围拒绝而非截断；金额和汇率不使用 JSON Number |
| Time | RFC 3339 UTC 字符串；持久化 timestamptz；业务时区单独保存 IANA 名称 |
| Digest | `sha256:` + 64 位小写十六进制；业务语义摘要基于 RFC 8785 JCS 的 UTF-8 |
| Page | `limit` 默认 25、最大 100；不透明 cursor 绑定过滤、排序和授权 Scope；按 `createdAt,id` 稳定排序 |

币种最小单位由版本化 Currency Metadata 决定。计算保留精度，最终支付/结算默认 half-even；风险预留朝增加负债方向舍入。领域可注册更严格范围或合法舍入方式，但不能静默丢失精度。超过精度的 Provider 原值保存在原始 Artifact，进入正式计算前显式拒绝或形成带规则版本的转换。

结构化摘要针对 Schema 声明的 payload 字段集合，排除摘要自身、外部签名和传输封套；文件摘要直接计算原始字节。集合型字段的排序/去重规则由 Schema 预先固定，普通数组顺序保留。禁止通过相互包含最终摘要定义 Invocation/Manifest 或 Package/CTK 的循环摘要。

## 2. 可信 Context

Context 由服务器创建，不接受客户端 JSON 中同名字段作为可信值。跨进程只传不可猜测的短时 Ref，由接收方经身份认证回源解析；Ref 本身不是 Bearer 授权。

| RequestContext 字段 | 必填与来源 |
|---|---|
| requestId / correlationId | 必填；服务端生成；合法上游 correlationId 可沿用 |
| causationId / traceId | 可选；关联父 Command/Event 与观测；不作为权限 |
| actingOrganizationId / resourceOrganizationId | 必填；分别为行为责任组织和数据 Owner；系统任务使用登记的系统组织上下文 |
| workspaceId | 跨组织时必填，必须覆盖当前关系；单组织可缺省 |
| actor | `{ type, id, responsibilityRef? }`；type 为 Human、AgentInvocation、Service、ExternalPlatform；身份来源由 Ingress 或 Workload Identity 确定 |
| purposeOfUse | 必填已登记用途；不得是任意自然语言 |
| authnStrength | 当前认证强度与已核实 MFA 时间；不能从 UI 自报 |
| sessionEpoch / scopeEpoch | 服务端当前撤权版本；无用户 Session 的 Service 使用自身 credentialEpoch 映射，不冒用人类 Session |
| executionAuthorityRef / originatingRequestRef | 长周期服务任务适用；前者为 AuthorityRef（Mission 或独立执行委托），后者为原始请求 Ref；均由服务端回源取得 |
| contextExpiresAt / receivedAt | 必填；任务每次唤醒重新创建上下文 |
| locale / businessTimezone | 展示与业务解释信息，不影响授权 |

AuthorizedRequestContext 在相同字段上增加必填 `authorizationSnapshotId`。Snapshot 必须绑定 actor、Target、用途、有效期、输入对象版本、Grant、两类 Policy、能力分配和 Epoch。RequestContext 中该字段必须缺省；客户端、Agent 和 Pack 不能签发两种 Context。

TenantContext 为服务端从已核实 RequestContext 派生的内部数据访问子集：`requestId, actor, actingOrganizationId, resourceOrganizationId, workspaceId?, purposeOfUse, sessionEpoch, scopeEpoch, contextExpiresAt`；不是公开可传入的 DTO，也不自行证明业务授权。一个租户 UoW 固定一个 resourceOrganizationId，Repository 与数据库 RLS 使用同一值；跨组织责任来源核对、部署目录及维护访问遵循[Data Plane 的 RLS/UoW 合同](28-Data-Artifact与Audit详细设计.md#11-数据库角色与-rls)，不能将组织列表当作任意跨租户查询权限。

## 3. Command、Query 与返回

Command Envelope：

~~~json
{
  "commandId": "6f1929c3-3cb2-44de-92c9-f8305d60b96d",
  "schemaVersion": "0.1.0",
  "type": "abh.mission.activate",
  "target": { "type": "abh.mission", "id": "6f1929c3-3cb2-44de-92c9-f8305d60b96e" },
  "expectedVersion": 3,
  "idempotencyKey": "caller-stable-key",
  "payload": { "authorityRef": { "type": "abh.mission-authority", "id": "6f1929c3-3cb2-44de-92c9-f8305d60b96f", "version": 1 } }
}
~~~

创建请求无 expectedVersion；所有既有聚合写入必填。commandId 由入口补全，HTTP 客户端只发送注册 Payload、Target、expectedVersion 与幂等键。目标类型、Payload 和权限不能由通用字符串动态调用任意代码。

HTTP Header `Idempotency-Key` 是 HTTP 的幂等键来源，`If-Match` 映射 expectedVersion；内部 Command 同源字段只生成一次。返回 ETag 为版本。Header/Body 重复且不一致时拒绝，不猜测优先级。

| 结果 | 语义 |
|---|---|
| 201 / 200 | 正式对象已提交；`{ success:true, data:{ objectRef, commandId, ... } }` |
| 202 | Command/Action 已持久受理；包含 trackingRef 和 Location；不表示外部副作用完成 |
| Query 200 | `{ success:true, data, meta:{ nextCursor?, asOf, watermark, stale } }` |
| Error | `{ success:false, error:{ code, category, message, retryable, details?, correlationId } }`；敏感对象存在性不泄漏 |

Query 明确 filter、排序、cursor、consistency（Strong 或 Projection）。Strong 只对内部事实读取成立，不承诺外部平台即时一致。列表不强制 total，避免高基数 count；统计作为单独 Query。

公开 Command 统一注册在 `POST /v1/commands/{commandType}`，请求 Body 为 Target/Payload，Header 按上述规则映射；模块声明 Internal 的 Command 不生成 HTTP 路由。公开 Query 使用各模块明确的资源路径，未单列路径的命名 Query 注册在 `GET /v1/queries/{queryType}`，仅接受已登记过滤字段。路由名、请求/返回 Schema、权限 Action 与错误码一起进入 Contract Registry，不允许运行时反射任意函数。

## 4. 幂等、事务与重复

唯一键为 `(resourceOrganizationId, actorPrincipalId, commandType, idempotencyKey)`。相同键和规范化 Payload/Target/expectedVersion 摘要返回原受理引用；不同摘要返回 IDEMPOTENCY_CONFLICT。响应重读仍执行当前权限裁剪，撤权后不能通过旧键读取敏感响应。

业务事务同时提交 Owner 状态、Command Receipt、必要 Audit 与 Outbox。通用 Command Receipt 默认保留 30 天；外部 Action/Operation 幂等映射按该资源完整存续及对账保留期保存，清理正文不删除重复写入的防护墓碑。客户端超时重发同键；只有业务意图改变才用新键。

所有表关系使用逻辑引用：服务层在同事务核对组织、对象版本与存在性；不使用物理外键。共享列为 id、resource_organization_id、version、created_at/by、updated_at/by、deleted_at/by。不可变记录只允许追加，revision 以新记录引用前项。

租户拥有的自然键、去重键、报告缓存键与复合索引均以 resourceOrganizationId 为边界；只有明确登记为部署级的 Pack/Capability/Schema 目录可用全局键。文档表中简写的键继承此规则。数据库列统一 snake_case，接口字段为 camelCase，Repository 映射；organizationId/ownerOrganizationId 在所属记录中均映射资源归属列，不新增并列租户真相。

既有对象的 expectedVersion 是 CAS 条件；授权与验证另记录真正参与判断的语义版本/摘要。Run/Action 状态推进和追加回执不能仅因聚合 version 增长就使自身所有授权失效；Goal/Payload/计划/责任/来源的实质变更仍必须重验。每个 Snapshot 的依赖字段集合由 Owner 契约明确，不能把全部聚合版本无差别当成冻结业务输入。

## 5. Event、Job 与 Port

Event 字段固定为 `eventId, type, schemaVersion, aggregateRef, aggregateVersion, occurredAt, correlationId, causationId, actorRef, actingOrganizationId, resourceOrganizationId, workspaceId?, payload`。payload 仅包含变化摘要和 Ref，不包含 Token、原始 Prompt 或可继承权限。

每聚合版本的多事件另有 `eventOrdinal`；顺序键为 aggregateId/version/ordinal。事件不是全局有序日志。消费方以 `consumerId,eventId` Inbox 防重；发现缺口先回读 Owner 版本和待处理事件，不采用最后写入覆盖。

Job 只携带 jobType、targetRef、commandRef、dedupeKey、notBefore、deadline、authorityRef、causeRef；Worker 唤醒后重新创建 Context。已过期的 Snapshot 不作为长期工作票据。

每个 Port 在对应模块定义 Caller、实现方、请求/结果、取消和失败语义。网络取消只代表停止等待；是否已发生外部效果由 Operation Outcome 判断。

## 6. Error Registry

以下为全局分类；模块特有代码须登记到机器 Registry 并映射其中一类：

| category | 通用 code | HTTP | 处理 |
|---|---|---|---|
| Validation | INVALID_ARGUMENT、SCHEMA_UNSUPPORTED、LIMIT_EXCEEDED | 400 | 修正输入，不重试 |
| Authentication | UNAUTHENTICATED、CONTEXT_EXPIRED | 401 | 重新认证/创建 Context |
| Authorization | FORBIDDEN、PURPOSE_DENIED、EPOCH_REVOKED | 403 | 权限变化后重新请求 |
| NotFound | RESOURCE_NOT_FOUND | 404 | 包含无权获知存在性的对象 |
| Conflict | VERSION_CONFLICT、IDEMPOTENCY_CONFLICT、ASSIGNMENT_AMBIGUOUS | 409 | 回读并重规划 |
| Precondition | PRECONDITION_FAILED、AUTHORITY_REQUIRED、CAPABILITY_UNAVAILABLE | 409 | 补足条件或正式责任 |
| Capacity | RATE_LIMITED、RESOURCE_EXHAUSTED | 429 | Retry-After；不能扩大权限 |
| Dependency | DEPENDENCY_UNAVAILABLE、DEPENDENCY_TIMEOUT | 503 / 504 | 安全可重试才重试 |
| Internal | INTERNAL_ERROR | 500 | 保留 correlationId；不输出内部堆栈 |

Unknown 是 Outcome，不属于 Error Registry。外部写入可能生效时，API 返回持久 Operation 的 trackingRef 与 outcome=Unknown；不能只返回 retryable=true 的网络错误。

默认安全读取/数据库冲突恢复最多初次调用后 3 次重试，退避基线 1/2/4 秒并加有界抖动；超过 Deadline 立即停止。SDK、队列和 Provider 只能有一个重试 Owner。模型重复调用必须重新预留费用；副作用重试规则由 Operation 模块覆盖，不能套通用重试。

## 7. 契约验收与演进

公开 API/Port/Schema 当前均为 Preview；Internal Controller/Repository 不从公共 exports 暴露。新增字段须有兼容默认；安全含义不明的新枚举拒绝处理并报告版本不兼容。纯展示可显示未识别状态，但不能据此放行 Command。

必须验证：重复 Command 只提交一次；同键异参冲突；跨组织 Ref 返回裁剪错误；缺少/伪造 Context 拒绝；乱序事件不回退版本；金额往返不损精度；HTTP、SDK、Job、Tool 使用同一错误与幂等语义。具体类型与 Golden Fixture 由 Contract Package 生成，本文不建立运行时第二套手写类型。
