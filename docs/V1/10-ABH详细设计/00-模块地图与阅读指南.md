## 1. 模块与部署

四个责任域保持 Agentic Core、Human Gateway、Trusted Runtime、Business Workbench；Domain Application 通过公开 SDK 装配领域语义。模块按独立 Owner、状态、接口或失败语义拆分，不按技术名词一词一服务。

本目录是责任与契约地图，模块优先由成熟开源组件和薄适配实现。业务 Owner 保留正式事实与验收责任；已由上游覆盖的通用机制不重复开发。复用选择、自研补缺和退出规则统一见 [ABH 自研边界](../00-总体设计/Agentic-Business-Harness总体设计.md#45-abh-自研边界)，实施时不把 33 份设计转换为 33 套自研基础设施。

    IN --> MC[Mission Controller]
    IN --> HG[Responsibility / Decision / Correction]
    MC --> RO[Run Orchestrator / Task Graph]

    RO --> PI[Pi Adapter]

    PI --> TG[Tool Gateway]

    PK -.versions.-> CR

M0 默认只有内置有界 Worker 的 server 和 PostgreSQL，Workbench 按需启用；M1 的真实写入拆独立 Worker。所有已启用模块共用同一 PostgreSQL 集群和受控 Schema，图中连线表达完整能力依赖，不能据此新建等量服务。

接入者先读 [SDK 最小作者流程](60-SDK与CTK详细设计.md#2-最小作者流程)与 [CLI 配置](61-CLI-Distribution与运维详细设计.md#3-配置-schema)。独立 Action 由现有应用经 Interaction 直接进入 Action Engine，无需经过 Mission/Pi；仅按已声明能力加载代码、任务和维护流程。以下模块地图服务于框架维护者，未启用的能力不成为接入前置条件。

## 7. 所有模块共同继承的实现合同

- HTTP/SDK/Job/Tool 使用 01 的同一 Envelope/错误合同；公开接口当前均 Preview，Internal 接口不开放网络入口。Schema 状态由 02/05 生成。
- Owner 的正常/拒绝/恢复流程均写必要 Audit，事件经 Outbox；Repository 强制 Tenant/Purpose，CAS/逻辑引用在事务内完成。
- 普通 Command 为同步持久受理，长操作返回 202/trackingRef；Port 的内部校验继承 NFR，外部调用必须有独立 Deadline/取消与 Outcome 合同。
- 表继承公共审计列、版本和软删除规则；任何无字段默认的生产 Grant、资源上限、Secret/身份配置均 fail closed。
- 配置默认属于部署内部、无秘密正文；除明确可热更新项外重启生效。降低上限/撤权必须立即作用于新工作，已固定 Run 按更严格当前控制执行。未知配置拒绝启动。
- 升级遵循 Expand/Backfill/Verify/Contract，保留兼容旧 Run/Operation 的证据；默认无项目遥测与未经配置的出站。
- 每个模块的责任角色在实现批次前绑定真实负责人；未校准的性能/外部最终性参数按 62 门禁记录，不能标记已经通过。
- 每个模块实现明确复用组件、必要补缺与删除条件；优先复用公开接口，每批验收检查可被上游替换的重复实现，沿用既有 CTK/迁移门禁。
